# Mentions and prompt shortcuts (iOS)

Read before changing @ references, `/` commands or prompt shortcuts in any composer. These rules bind every caller of the area, not only files in its directory.

- @ references follow Notion: `Chat/ChatMentionPanel` is docked at the composer's bottom edge, directly on the keyboard, with the prompt above it (`ChatComposerLiquidGlassSurfaceLayout.setBottomInset` lifts the surface by `ChatMentionPanel.dockHeight`). In the conversation the composer never grows past the page header (`ChatComposerView.fitPageRoom`, rerun from `LodyChatView.layoutSubviews` when the keyboard or header moves): the panel gives up rows first, down to `ChatMentionPanel.minimumDockHeight`, since its lists scroll; then the input stops growing and scrolls, down to one line. While the composer has no room under the header, the connection status and scroll-to-bottom controls above it hide (`ChatOverlay.crowded`). `mentions-room` checks both `@` and `/`, including a multi-line draft. It hosts a contained `UINavigationController` of `ChatMentionLevelController` lists (diffable `UICollectionViewListCell`s, `UIContentUnavailableConfiguration` when empty): the root shows the categories (typed text shows matches), a category or folder pushes its level with the native push transition and back button, and a folder level leads with "Reference folder". The system bar is hidden (far too tall for the 280 pt panel): deeper levels draw a 44 pt header (plain back chevron + title + hairline) above their list, opaque so the covered level never shows through the push, and the edge swipe still pops. Role rows lead with the Role's emoji (runtime mention items carry `emoji`). Prompt shortcuts (runtime `cmd` items inserting `/shortcut:<slug>`) list as their own "Prompt Shortcuts" category; `/` offers both, shortcuts first. The runtime lists every readable shortcut whose saved project, computer and agent scope matches the composer (web `resolveShortcutAvailability`), including ones whose body carries references, since choosing one inserts them as chips; it answers from its last listing while reading a fresh one, and a listing missing one owner's index is incomplete rather than empty, so it never replaces the cached shortcuts. Root categories and typed matches lead with Agent Roles and Prompt Shortcuts, then files, skills, conversations, issues, PRs and the agent's commands. Roles and shortcuts are workspace-wide, so `MentionCatalogStore` shows the last accepted lists (`MentionWorkspaceCache`: memory plus an account/workspace-scoped `SettingsSnapshotStore`) at once while each composer reads its own; a Role read made before presence is live never replaces cached Roles, and cached rows only display. When a host cannot fit the composer and the panel above the keyboard (the new-chat card on a short screen), the panel ends its lists at its own `keyboardLayoutGuide` so the last rows stay reachable; it never moves the composer. `$`, `￥` and `¥` open skills directly, as on web. Rows never take focus, so the keyboard stays; the text after the trigger filters the visible level; losing the trigger hides the panel and pops to the root. The old category page (`MentionPickerController`) is no longer opened from the composer. Android mirrors the panel, its order and an in-memory workspace cache (`chat/MentionPanel.kt`).

- `/` lists prompt shortcuts before the agent's commands. A conversation's commands are its session's reported list (`acpRuntimeConfig.availableCommands`, an empty list included) once the agent reported it, otherwise its Agent Config's probe preview (web `useAvailableCommands`). Choosing a shortcut writes its body, as web's `prepareShortcutSelection`: `ChatMentionPanel.loadShortcut` (`PromptShortcutsController.body`, runtime `promptShortcuts` `select`, which checks the id against the runtime's last listing, as web checks its live snapshot, and answers from the prefetched bodies without an index read) and `ChatShortcutInsertion.segments` turn the prompt and its references into text and chips (files `@path`, skills `$name`, issues / PRs `#number`, Agent Roles labelled). While the panel shows, it reads the listed shortcuts' bodies ahead, keyed by id and the listed `revision` (runtime mention items carry it) and dropped when it hides, so a choice writes the body over the trigger synchronously and an edited shortcut is read again. A choice whose body is not read yet replaces the trigger at once with a chip named for the shortcut that sends `/shortcut:<slug>`, which the runtime expands at send; the arriving body replaces only that chip node (`ChatComposerInput.replaceReference`), never text typed meanwhile, and nothing happens if the chip was deleted or sent. If the read fails the chip stays. An Agent Role chip reads as its emoji and name but sends `@role:<id>` (`ChatComposerInput.labelledReferences`, substituted in `markdown`, kept in the draft envelope), which the runtime expands at send.

- A reference in the composer reads as a chip, not tinted text alone: `ChatReferenceNode` carries `.lodyReferenceChip` and `ChatReferenceNode.registerChipDrawing` (registered in `ChatComposerInput.makeEditorView`) draws a rounded accent-tinted background behind each line's run, with the label in the accent colour. Every reference kind (files, folders, skills, Agent Roles, conversations, issues, PRs) uses the same chip.

- A sent message keeps its chips: user bubbles draw the same rounded chip (`ChatReferenceChipsView` in `ChatMessageContent`, from `.lodyReferenceChip` set by `ChatUserMentions`) behind runtime references and recognised `@path` / `$skill` / `#n` text. Until the runtime's turn arrives, the local bubble shows the composer's text, never its wire tokens: the send payload carries `displayText` and the chips' ranges (`ChatComposerInput.chipReferences`), kept on the Outbox send (a new chat's `CreateDraftRecord` included, which also titles the chat from `displayText`) and drawn by `ChatPendingSend.rows`. The runtime expands the reference tokens in `text` on every send.

- Sending rechecks reference catalogs against healthy workspace metadata and each referenced computer. After a definite reference failure, Retry resolves the original tokens again with the same input ID, attachments, quote cards and turn configuration. Unconfirmed inputs use delivery reconciliation.
