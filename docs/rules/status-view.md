# Status view and pin sections (iOS)

Read before changing the Home Pinned area, the Status grouping (Focus / Later / Settled), their gestures, menus and sheets, or the conversation page's status actions. Intended behavior: Lody `specs/sidebar-status-view.md` (Phones) and `specs/pinned-session-sections.md`; design and JSON contract: Lody `.agents/notes/proposed/architecture/2026-11-21-status-view-on-phones.md`. These rules bind every caller of the area, not only files in its directory.

- The shared runtime computes the list (contract: `packages/cloud-runtime/src/contract/status-view.ts`, behavior: its README's "Status view"). The catalog snapshot carries `statusView: { mine, team, nowMs, sectionsLoaded }` and `pinSections` (definitions in render order), decoded in `Sessions/StatusView.swift` (`StatusViewLayouts`, lossy per row and per section). Swift never sorts or classifies these rows: the Pinned area in every grouping and the whole Status grouping list exactly the layout's sections, rows and children in its order (`InboxSections.home` with `layout`). Only time and project buckets keep native grouping, and they skip every id the layout pins. Without a layout (a runtime or catalog cache older than it) Pinned falls back to the flagged families and Status to time buckets; never reintroduce a native tier classifier.

- Session content (title, project, branch, PR, status mark) comes from the catalog; unread, activity time, the Later countdown and the offered actions come from the layout row (`InboxSections.decorate`). Layout times are on the server clock: `StatusViewClock` learns its offset from the catalog's and `snoozePresets()`'s `nowMs` and ignores offsets beyond ten minutes, which come from a catalog restored from cache rather than skew. Countdowns, relative ages, the past-time check and resolved times shown to the person use it. The local viewed watermark still clears unread emphasis. Rows the catalog lacks are skipped; an Outbox creation the catalog has not read back (`SessionItem.pending`) shows at the top of Focus.

- Pin sections are list sections `pinned` (the default) and `pinned:<id>`; a user section stays as a labelled, empty drop target. Focus, Later and Settled are `focus`, `later` and `settled`. Later and Settled start collapsed and show their count while collapsed (`ChatGroupFolds`, device-local); Settled folds past `settledLimit` top-level rows behind Show all. A section's scope-hidden count is a non-interactive line under its rows.

- Writes are `StatusViewCommand`s sent through `SessionSource.statusCommand` to the runtime's `statusViewCommand` with the current Home `scope`, because a move's `beforeId` (the row it lands in front of, nil for the end; never an index or a key) resolves against that list. The runtime plans keys, jitter and opened-children rules against its replica and returns `{ writes }`; 0 means it refused the command or changed nothing, so a held drop is released and no Undo is offered. `StatusViewRuntime` decodes the command JSON into the generated params. Later presets come from `snoozePresets()`.

- Offer status actions only from the row's `canManage`, pin placement only from `canPrefer`, and section management only from the layout's `canManageSections` once `sectionsLoaded`. The runtime cannot see the member's role: `DataRuntime` passes `start({ workspaceReadOnly })` from the member list's role (`WorkspaceMember.readOnly`: `viewer`, `read` or `guest`), and Home applies the same flag to the layout (`StatusViewLayout.readOnly`) when the role arrives after the runtime started. Read-only rows have no status swipe, menu, drag or accessibility move.

- On movable rows, a stationary long press opens the menu on release: Later ▸ (presets with resolved times, Custom time…, Move to Focus while snoozed), Settle or Move to Focus, Pin / Unpin, Move to Section ▸ (top of another section, or New Section…), Move to Top, then the existing items. Moving while pressed starts a local UIKit drag (`ChatListStatusHooks`): only top-level rows lift, Focus reorders, pin sections reorder and exchange rows, a drop into the Pinned area pins, and a Later or Settled row dropped into Focus is restored. Pinned rows leave through Unpin. Dropping on a group label inserts at the top, including empty and collapsed groups. Each crossed slot ticks a selection haptic. VoiceOver rows offer Move up and Move down within their area.

- While a drag is in flight the list defers incoming projections and applies the latest when it ends. A drop, Move to Top, Move to Section or accessibility move shows its order at once through `StatusViewHold` until the catalog shows the row there, the write fails, or a newer layout arrives after the write was accepted.

- Trailing swipe: Settle and Later on Focus and Later rows, Archive on Settled rows; leading swipe pins or unpins. Never full-swipe.

- Later opens a bottom sheet with the presets and a custom date and time; past times are refused there and again before sending. A preset picked from the menu is resolved again first. Settle and Later confirm with an Undo notice that restores the previous tier (`StatusViewPlanning.undo`). When the conversation has active opened sub-conversations, Settle, Later and Move to Focus first ask, as desktop, whether they follow; drags never ask.

- Pin section labels carry a ⋯ menu: New Section… on every section; Rename, Move Up, Move Down and Delete on user sections (the default section stays first). Sections reorder only through Move Up / Move Down; deleting asks first and its conversations return to the default section.

- The conversation page's More menu carries the row's Later / Settle / Move to Focus, read from whichever scope's layout lists it.

- Verification: `apps/ios/verification/kit/session-rows` covers decoding (including the runtime's `contract/fixtures/catalog-status-view.json`), row mapping, read-only gating, the server clock, drop and accessibility planning, holds, undo, countdown, and command JSON. Launch the offline Home scene with `--ui-verify --ui-review-status`. Add `--ui-review-status-long` for a scrollable Focus list or `--ui-review-status-hold` to acknowledge moves and delay their publication. The hold fixture commands `status-catalog-repeat` and `status-catalog-readback` publish the old and accepted order, respectively.
