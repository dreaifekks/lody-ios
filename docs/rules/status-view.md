# Status view and pin sections (iOS)

Read before changing the Home Pinned area, the Status grouping (Focus / Later / Settled), their gestures, menus and sheets, or the conversation page's status actions. Intended behavior: Lody `specs/sidebar-status-view.md` (Phones) and `specs/pinned-session-sections.md`; design and JSON contract: Lody `.agents/notes/implemented/architecture/2026-11-21-status-view-on-phones.md`. These rules bind every caller of the area, not only files in its directory.

- The shared runtime computes the list (contract: `packages/cloud-runtime/src/contract/status-view.ts`, behavior: its README's "Status view"). The catalog snapshot carries `statusView: { mine, team, nowMs, sectionsLoaded }` and `pinSections` (definitions in render order), decoded in `Sessions/StatusView.swift` (`StatusViewLayouts`, lossy per row and per section). Swift never sorts or classifies these rows: the Pinned area in every grouping and the whole Status grouping list exactly the layout's sections, rows and children in its order (`InboxSections.home` with `layout`). Only time and project buckets keep native grouping, and they skip every id the layout pins. Without a layout (a runtime or catalog cache older than it) Pinned falls back to the flagged families and Status to time buckets; never reintroduce a native tier classifier.

- Session content (title, project, branch, PR, status mark) comes from the catalog; unread, activity time, the Later countdown and the offered actions come from the layout row (`InboxSections.decorate`). Layout times are on the server clock: `StatusViewClock` pairs the catalog's `nowMs` with the device instant the catalog was received (`syncedAt`, kept with the cached catalog, so a restored cache calibrates correctly) and `snoozePresets()`'s `nowMs` with the reply's arrival; the newest sample wins and any skew is accepted. Countdowns, relative ages, the past-time check and resolved times shown to the person use it. The local viewed watermark still clears unread emphasis, and the row keeps the dot for its own or its internal Tabs' unread output (`SessionRows.treeRows`) as well as for the layout's woken snooze. Rows the catalog lacks are skipped; an Outbox creation the catalog has not read back (`SessionItem.pending`) shows at the top of Focus.

- Pin sections are list sections `pinned` (the default) and `pinned:<id>`; a user section stays as a labelled, empty drop target. Focus, Later and Settled are `focus`, `later` and `settled`. Later and Settled start collapsed and show their count while collapsed (`ChatGroupFolds`, device-local); Settled folds past `settledLimit` top-level rows behind Show all. A section's scope-hidden count is a non-interactive line under its rows.

- Writes are `StatusViewCommand`s sent through `SessionSource.statusCommand` to the runtime's `statusViewCommand` with the current Home `scope`, because a move's `beforeId` (the row it lands in front of, nil for the end; never an index or a key) resolves against that list. The runtime plans keys, jitter and opened-children rules against its replica and returns `{ writes }`; 0 means it refused the command or changed nothing, so a held drop is released and no Undo is offered. `StatusViewRuntime` decodes the command JSON into the generated params. Later presets come from `snoozePresets()`.

- Offer status actions and session management (Settle, Later, Archive, Rename, Delete) only from the row's `canManage`, pin placement only from `canPrefer`, and section management only from the layout's `canManageSections` once `sectionsLoaded` (`InboxSections.restrict`, also on time and project rows). The runtime cannot see the member's role: `DataRuntime` passes `start({ workspaceReadOnly })` from the member list's role (`WorkspaceMember.readOnly`: `viewer`, `read` or `guest`). When the role arrives after the runtime started, Home and the conversation page apply the same flag to the layout (`StatusViewLayout.readOnly`, `lodyWorkspaceRoleDidChange`); re-sending `start` is not an option, because it restarts the runtime's accepted Roost inputs. Read-only rows have no status swipe, management menu item, drag or accessibility move.

- On movable rows (iOS 17.4+), a long press that UIKit has not turned into a drag opens the menu on release; earlier systems cannot present a menu from code and keep the system context menu, which still turns into the drag when the lifted row moves. The menu: Later ▸ (presets with resolved times, Custom time…, Move to Focus while snoozed or settled), Settle or Move to Focus, Pin / Unpin, Move to Section ▸ (top of another section, or New Section…), Move to Top, then the existing items. Later is offered on every tier. An opened child carried under a pinned opener is not pinned itself: it offers Pin, its own Later / Settle / Move to Focus, and no Move to Section. Moving while pressed starts a local UIKit drag (`ChatListStatusHooks`): only top-level rows lift and their expanded opened children leave the list for the drag; Focus reorders, pin sections reorder and exchange rows, a drop into the Pinned area pins, a Later or Settled row dropped into Focus is restored, and a pinned row dropped into Focus is unpinned there. Dropping on a group label inserts at the top, including empty and collapsed groups; a drop in front of an Outbox creation the layout does not list also means the top. Between rows the list opens the landing gap. Each crossed slot ticks a selection haptic, including while the edge scroll moves rows under a still finger; the edge scroll stops at the content's end and when the app resigns active. Outside the Status grouping only Pinned rows reorder (drag, Move to Top, Move up / down). VoiceOver rows offer Move up and Move down within their area.

- While a drag is in flight the list defers incoming projections and applies the latest when it ends. A drop, Move to Top, Move to Section or accessibility move shows its order at once through `StatusViewHold` until the catalog shows the row there, the write fails or writes nothing, or, once the write was accepted, a layout moves the row (catalog updates that leave it where it was keep the hold); an accepted hold that never reads back yields after five seconds. Each moved row holds independently. A read-back for another local move can change its neighbours while leaving its hold in place.

- Trailing swipe: Settle and Later on Focus and Later rows, Move to Focus and Archive on Settled rows; leading swipe pins or unpins. Never full-swipe.

- Later opens a bottom sheet with the presets and a custom date and time; past times are refused there and again before sending. A preset picked from the menu is resolved again first. Settle and Later confirm with an Undo notice that restores each changed conversation's own previous tier, the opened sub-conversations included one by one (`StatusViewPlanning.undo`). When the conversation has active opened sub-conversations, Settle, Later and Move to Focus first ask, as desktop, whether they follow; drags never ask.

- Pin section labels carry a ⋯ menu (a UIKit button on the header cell whose 44 pt target overhangs the label, so labels with and without it keep the same height and spacing): New Section… on every section; Rename, Move Up, Move Down and Delete on user sections (the default section stays first). Sections reorder only through Move Up / Move Down; deleting asks first and its conversations return to the default section.

- The conversation page's More menu groups the row's Later / Settle / Move to Focus under a single Conversation status submenu (`session.status.title`), placed directly above Archive and read from whichever scope's layout lists it; on a Tab it acts on the Tab's conversation. Seeing the page sends read receipts (`StatusViewRead`): the page's conversation up to its latest message, and its root conversation up to a woken snooze unless the root's own messages are still unread on a Tab page.

- Verification: `apps/ios/verification/kit/session-rows` covers decoding (including the runtime's `contract/fixtures/catalog-status-view.json`), row mapping, Tab unread, carried children, read-only gating, the server clock, read receipts, drop and accessibility planning, holds, undo, countdown, and command JSON. Launch the offline Home scene with `--ui-verify --ui-review-status`. Add `--ui-review-status-long` for a scrollable Focus list or `--ui-review-status-hold` to acknowledge moves and delay their publication. Add `--ui-review-status-family` for a carried child, `--ui-review-status-pending` for a pending creation, or `--ui-review-status-undo` for an opener and child in different tiers. The hold fixture commands `status-catalog-repeat` and `status-catalog-readback` publish the old and accepted order, respectively.
