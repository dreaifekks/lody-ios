## LAN hub (fork)

- Besides official Lody Cloud, this fork joins a self-hosted LAN hub. `AuthSession` in `packages/LodyKit/Sources/LodyKit/Auth` owns the mutually exclusive account mode. A successful LAN join replaces Cloud credentials; successful Cloud authorization removes the LAN. Failed or cancelled authorization keeps the current account. Credentials remain in `AuthKeychain` under the `lan-hub` account; UIKit receives `AuthAccount.lan` summary only.
- `LanInvite` stays compatible with Lody's `parseLanInvite`, `deriveLanHubId` and `deriveLanHubUserId`: `lody-lan://<token>@host:port[/<name>]` or `lody-lans://` for HTTPS, workspace `lw_<id>`, user `local:<id>`. UIKit onboarding lives in `packages/LodyKit/Sources/LodyKit/Onboarding`; use the existing `LodyShell` presentation and injected service boundary.
- `DataRuntime` in `LodyKit` owns the offscreen WebView and loads LAN content at `lody-hub://<id>/`. `LanHubSchemeHandler` forwards `/ds/*` and `GET`/`HEAD /api/time` (for server clock sync; `OPTIONS` stays local and unauthenticated) to the hub with native bearer injection. The WebView receives a placeholder token and its own origin, never the long-lived LAN credential. Foreground `reconnect()` drops old hub connections before retrying; logout and unsubscribe invalidate the owned runtime.
- `LanHubFollower` checks `/lan/where` on start, foreground and catalog sync errors. Follow only authenticated `movedTo` addresses and terms; prefer later terms, then the lexically smaller address. When the hub is unreachable, query members' TLS 1.2 PSK `hub` service and probe the address. Session reads below a restored or compacted stream's start (410 `gone`) bootstrap again. Keep HMAC/term and invite swiftc checks in `apps/ios/verification/kit`.
- Preserve fork cloud-runtime semantics in `packages/cloud-runtime`: heartbeat presence, human input receipts/authors, Role target identity and same-machine instances, Role-session replies and Continue after a machine restart. Network read failures retain replicas and cursors, with `STALL_GRACE_MS` before reporting not-live; protocol errors or the 8 MiB ceiling bootstrap again. Preserve the upstream subscription-owner fence and native watchdog.
- Only hub-acknowledged writes enter live replicas. Turns, pointers and dispatch use `appendOnce`; stage pointers on scratch replicas, then join after ACK. Persist history before pointer and RPC. Confirm an ended attempt from a fresh read before resolving unknown; never automatically replay writes after recovery. Missing turns fail for an explicit retry under a new id. Release outbox inflight before returning pre-write not-ready/retryable results to waiting.
- LAN has no Cloud account, billing, published sharing, preview or blob service. Hide those entries (and Prompt Shortcuts until `lan-hub` supports UserSpace streams) when `account.lan` is set. Keep text reading, creation and replies available for every desktop-produced session. GitHub credentials come from the hub `/github/token`. Do not route LAN files through Cloud blob storage; the LAN file/member transport is separate.
- LAN files live in `packages/LodyKit/Sources/LodyKit/LAN`: `LanFileChannel` shares `LanMemberChannel` TLS-PSK/hello and requires `protocolCapabilities.lanFiles`. Chat, new-session and Share hosts share an eight-total-attachment budget. Use the same ImageIO payload preparation as Cloud; local blocks preserve machine, storage session, size and digest. Read kept bytes from the block's member; never send a LAN reference to Cloud blob storage.
- Attachment UI identity and image disk namespaces are stable account/mode/workspace identities. Runtime owner/generation belongs only to in-flight I/O fencing. A runtime recovery must not strand an editor/preview or hide an already cached digest. Cache notifications and image consumers use the same stable identity; account changes still reject late results.
- LAN terminal UI lives in `packages/LodyKit/Sources/LodyKit/Terminal` and `packages/LodyKit/Sources/LodyKit/Sessions`, with `LanTerminalLink` in `LAN`. The page owns only its shell ID across reconnects: list/adopt/attach that ID, close it on completion, and never use `close_session` to clean up. Refresh the member endpoint from current catalog on each explicit reconnect. Unknown open outcomes are not guessed or automatically replayed. Keep the scoped-shell TLS loopback check and temporal UI case; SwiftTerm is an SPM dependency pinned to 1.19.0.
- `LanPush` and APNs/ActivityKit ownership stay under `packages/LodyKit/Sources/LodyKit/Notifications`. Register device and Live Activity tokens with the hub, refresh on foreground and after following a moved hub, and remove the old registration when leaving. Preserve recipient/account fencing and remove settled permission notices. Never initialize live push providers for offline Debug fixtures.
- Share Extension continues to use only the credential-free `ShareStore` App Group snapshot and inbox. It never accesses LAN credentials, Keychain, networking or the runtime. LAN sends drain through the app's ordinary outbox. All App Group readers (Share, diagnostics, preferences and Live Activity) use the identity derived during `pnpm prebuild`; keep upstream defaults and support `LODY_BUNDLE_ID` / `LODY_APPLE_TEAM_ID` overrides.
- Voice input uses upstream's native on-device `SpeechTranscriber` (`SpeechDictation.swift` + `ChatComposerDictation.swift`); do not reintroduce WebRTC/Codex voice.
- Only commit task changes; do not push, tag or publish without the user's instruction. On the Mac mini, take `/tmp/lody-ios-mac-heavy.lock` before heavy native work, wait while one-minute load exceeds 30, and run only one xcodebuild and one simulator. Never remove a lock held by another task. LAN runtime checks target a loopback `loro dev` only, never the user's real hub.
